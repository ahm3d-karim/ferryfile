# Distribution channels

Every channel ships the assets of a published GitHub release:

| Channel | Ships | Updated by |
| --- | --- | --- |
| GitHub Releases | `Ferryfile_<v>_x64-setup.exe`, `Ferryfile_<v>_x64-portable.zip`, `.sha256` files | [`release.yml`](../.github/workflows/release.yml) on a `v*` tag (drafts the release) |
| npm (`ferryfile`) | A small launcher that downloads the portable zip on first run | [`channels.yml`](../.github/workflows/channels.yml) when the release is published |
| winget (`Ferryfile.Ferryfile`) | The installer | `channels.yml` (after the first manual submission) |
| Scoop | The portable zip | The bucket repo's own workflow (polls for new releases) |

## Releasing

1. Bump `version` in `src-tauri/tauri.conf.json` (and `Cargo.toml`), open a PR, merge.
2. Tag `main` and push the tag (`git tag v0.2.0 origin/main`, then
   `git push origin v0.2.0`). `release.yml` builds, signs if SignPath is set up,
   and drafts the release.
3. Check the draft and **publish** it. `channels.yml` then pushes to npm and
   winget; Scoop catches up within a few hours.

## One-time setup

### npm

The package is `ferryfile`; it installs a `ferryfile`
command. The very first publish can't use trusted publishing yet:

1. Create an npm account with 2FA, then a **granular access token** with
   publish rights, and add it as the repository secret `NPM_TOKEN`.
2. Set the repository variable `PUBLISH_NPM` to `true`.
3. After the first publish, on npmjs.com open the package's **Settings →
   Trusted publishing**, add GitHub Actions for `ahm3d-karim/ferryfile` with
   workflow `channels.yml`, then delete the `NPM_TOKEN` secret. Later
   publishes authenticate with OIDC and carry provenance.

To publish a release that's already out: **Actions → Publish channels → Run
workflow** with its tag.

### winget

winget only accepts updates from automation once the package exists, so the
first version is submitted by hand:

1. Generate manifests for the published release:
   `./scripts/channel-manifests.ps1 -Tag v0.1.0`
2. Submit `packaging/winget/manifests/f/Ferryfile/Ferryfile/<version>/` as a PR to
   [microsoft/winget-pkgs](https://github.com/microsoft/winget-pkgs), for
   example with `wingetcreate submit <folder>` or by hand from a fork.
   Microsoft's bots validate it and a moderator merges it, usually within a
   few days.
3. Then for automatic updates: keep a fork of `microsoft/winget-pkgs` under
   your account, create a **classic** personal access token with the
   `public_repo` scope, add it as the secret `WINGET_TOKEN`, and set the
   variable `PUBLISH_WINGET` to `true`.

### Scoop

Scoop installs from a "bucket" repository. The bucket for Ferryfile is
`ahm3d-karim/scoop-ferryfile`; it contains `bucket/ferryfile.json` (generated by
`./scripts/channel-manifests.ps1`) and a scheduled workflow that updates the
manifest from new GitHub releases using its `checkver`/`autoupdate` rules.
Users install with:

```powershell
scoop bucket add ferryfile https://github.com/ahm3d-karim/scoop-ferryfile
scoop install ferryfile/ferryfile
```

## Signing

The portable zip's `ferryfile.exe` is not signed; only the installer is (see
[CODE_SIGNING.md](../CODE_SIGNING.md)). npm and Scoop downloads aren't
browser downloads, so Windows SmartScreen doesn't prompt for them.
